# 多言語対応（英語・日本語）

更新日: 2026-11-16

このサイトは **英語を既定言語**、日本語を第2言語として、同じデータから両方を生成します。
両言語とも URL 接頭辞を持ちます（`/en/…` と `/ja/…`）。サイト直下 `/ai-plan-radar/` は
`/ai-plan-radar/en/` へ即時に転送します。

- 英語: https://tonbiattack.github.io/ai-plan-radar/en/
- 日本語: https://tonbiattack.github.io/ai-plan-radar/ja/

## 1. ファイル構成

| ファイル                  | 役割                                                             |
| ------------------------- | ---------------------------------------------------------------- |
| `src/i18n/locale.ts`      | 言語の定義、`<html lang>`、OGP ロケール、URL の付け外し          |
| `src/i18n/messages.ts`    | **画面文言**（見出し・ボタン・凡例・説明文）。英語が型の基準     |
| `src/i18n/data-en.json`   | **データ中の日本語文字列の英訳**（説明文・注記・単位・期間など） |
| `src/i18n/data.ts`        | カタログを表示言語へ変換する `localizeCatalog()` と翻訳ヘルパー  |
| `src/pages/[locale]/`     | 全ページ。`getStaticPaths()` が `en` と `ja` を返す              |
| `src/pages/index.astro`   | サイト直下から `/en/` への即時転送                               |
| `tests/unit/i18n.test.ts` | 翻訳漏れ・キー欠落・プレースホルダー不一致の検出                 |

Astro の `i18n` 設定（`astro.config.mjs`）で `defaultLocale: 'en'`、
`prefixDefaultLocale: true` を指定しています。

## 2. 何を翻訳し、何を翻訳しないか

**翻訳する**

- 画面文言（`src/i18n/messages.ts`）
- サービス概要、プランの注記、税・キャンペーン表記、利用枠の指標・単位・期間・
  リセット/超過/繰越の説明、機能名、モデル別注記（`src/i18n/data-en.json`）
- ベンチマークの説明・指標名・注記（`src/i18n/data-en.json`）
- プラン名・対応環境・モデル表示名に含まれる日本語（例: `本体（オープンソース）`、`（系列）`）

**翻訳しない（固有名詞・事実）**

- サービス名、モデル ID、slug、出典 URL
- 金額・通貨・請求周期・確認日
- ベンチマークのスコア・コスト

料金は **元の通貨のまま** 表示し、為替換算は一切しません。翻訳によって価格や
通貨が変わることはありません。

## 3. 未調査・非公開・利用不可・制限なしの意味を保つ

これらは別々の状態として両言語で訳し分けます。

| データ上の値   | 英語                    | 日本語                   |
| -------------- | ----------------------- | ------------------------ |
| `undisclosed`  | Not disclosed           | 非公開                   |
| `unresearched` | Not researched          | 未調査                   |
| `unavailable`  | Not available           | 利用不可                 |
| `unlimited`    | No limit (where stated) | 制限なし（対象範囲のみ） |
| `failed`       | Check failed            | 確認失敗                 |

「不明」をゼロや無制限として表示しない方針は言語を問わず共通です。

## 4. データ更新の手順

`src/data/catalog.json` などは **日本語のまま1か所だけ** 更新します。英語は
辞書から引くため、二重入力は不要です。

1. `src/data/*.json` を更新する（日本語で記述）
2. `npm run check` を実行する
3. 英訳漏れがあればビルドが次のエラーで止まる

   ```
   Error: Missing English translation for: （該当の日本語文字列）
   ```

4. 表示された文字列を `src/i18n/data-en.json` に追記する

   ```json
   "新しい日本語の注記。": "The English note.",
   ```

5. 再度 `npm run check`

### 画面文言を追加する場合

`src/i18n/messages.ts` の `en` と `ja` の両方に同じキーを追加します。`en` が型の
基準なので、`ja` 側にキーやプレースホルダーが足りないと `astro check` と
`tests/unit/i18n.test.ts` が失敗します。

プレースホルダーは `{name}` 形式で、両言語で同じ名前・同じ個数にしてください。

```ts
// en
counts: {
  services: '{count} services';
}
// ja
counts: {
  services: '{count}件のサービス';
}
```

描画時は `interpolate(t.counts.services, { count: n })` を使います。

## 5. 言語切替 UI

ヘッダーの言語リンクは同じページのもう一方の言語へ移動し、**クエリ文字列
（検索語・絞り込み・比較対象・表示形式）をそのまま引き継ぎます**。
ビルド時点ではクエリを持てないため、`Layout.astro` の小さなスクリプトが
`location.search` を付与します。JavaScript が無効な場合も、言語を切り替えた
同じページへは移動できます（絞り込み条件は引き継がれません）。

## 6. SEO

- `html lang` は表示言語（`en` / `ja`）
- `canonical` は各言語の URL
- `hreflang` は `en` / `ja` / `x-default`（`x-default` は英語）
- OGP は `og:locale` と `og:locale:alternate`
- `sitemap.xml` は両言語の URL を `xhtml:link` 付きで列挙
- 英語の title / description は国際向けの検索語（pricing, plans, usage limits）を含む

## 7. テスト

```sh
npm test          # 翻訳網羅・キー一致・固有名詞/価格の保持を検証
npm run test:e2e  # PC/モバイルで両言語の直リンク・言語切替・SEO を検証
```

E2E は `/en/` と `/ja/` の両方について、トップ・モデル性能・詳細への直リンクが
GitHub Pages のサブパスで開けることを確認します。
