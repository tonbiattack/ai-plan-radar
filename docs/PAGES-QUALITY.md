# GitHub Pages と公開品質の確認

確認日: 2026-11-16

## GitHub Pages の利用条件

[GitHub Pages limits](https://docs.github.com/en/pages/getting-started-with-github-pages/github-pages-limits)（2026-11-16 確認）の要点:

- Pages は、商取引の促進を主目的とするサイト、eコマース、商用 SaaS の無料ホスティングとしては使用できない。
- パスワードやクレジットカード番号などの機微な情報を送信する用途には使わない。
- GitHub 利用規約（および卑猥な内容・暴力的な内容などの制限）に従う。
- 公開サイトのサイズ上限は 1 GB。ソースリポジトリの推奨上限も 1 GB。
- 帯域は月 100 GB のソフト制限。デプロイは 10 分でタイムアウトする。
- ビルドは 1 時間あたり 10 回のソフト制限があるが、**カスタム GitHub Actions ワークフローでビルド・公開する場合は適用されない**。本サイトはカスタムワークフロー（`.github/workflows/pages.yml`）を使う。
- アクセス集中時は 429 を返すことがある。

### 現状のサイトとの照合

ビルド成果物（`dist/`）を機械的に確認した結果:

| 項目                         | 実測                                                                  | 判定                          |
| ---------------------------- | --------------------------------------------------------------------- | ----------------------------- |
| 公開ファイル数               | 69（HTML 60）                                                         | 上限に対して十分小さい        |
| 合計サイズ                   | 1.5 MB                                                                | 上限 1 GB 以内                |
| 決済・課金処理               | なし（`stripe` / `paypal` / `checkout` 等の記述なし）                 | 商取引サイトに該当しない      |
| 認証・パスワード入力         | なし                                                                  | 機微情報を送信しない          |
| フォーム                     | 絞り込み用の `role="search"` のみ。送信先なし（クライアント側で完結） | データ収集なし                |
| アクセス解析・外部スクリプト | なし（`gtag` / `analytics` / 外部 `script src` いずれも 0 件）        | Cookie 同意や第三者送信が不要 |
| 外部通信                     | 各サービスの公式サイトへの通常リンクのみ                              | 静的配信の範囲                |

現状は「認証・決済・データ収集を持たない情報提供サイト」で、上記の禁止用途には該当しないと判断した。ただし適合性を保証するものではない。**商用化、広告、アフィリエイト、決済、会員登録、アクセス解析の導入時には再確認が必要**。規約自体も変更されうるため、公開前や四半期ごとの確認を推奨する。

## Lighthouse

Lighthouse 13.6.0、モバイル設定（`formFactor: mobile`、`throttlingMethod: simulate`）、ヘッドレス Chrome で測定した。数値は環境や実行ごとに変動する。

### 測定結果（ローカルのビルド済みサイト、2026-11-16）

| 対象                                 | Performance | Accessibility | Best Practices | SEO |
| ------------------------------------ | ----------: | ------------: | -------------: | --: |
| `/en/`（英語トップ）                 |         100 |           100 |            100 | 100 |
| `/ja/`（日本語トップ）               |         100 |           100 |            100 | 100 |
| `/en/models/`（モデル性能）          |         100 |           100 |            100 | 100 |
| `/en/services/kiro/`（サービス詳細） |         100 |           100 |            100 | 100 |

`/en/` の主要指標は LCP 0.8 秒、CLS 0、TBT 0 ms。再実行 3 回とも全カテゴリ 100 だった。

### 公開サイトの実測（2026-11-16）

デプロイ後の `https://tonbiattack.github.io/ai-plan-radar/en/` を同じ設定で測定した。

| 対象        | Performance | Accessibility | Best Practices | SEO |
| ----------- | ----------: | ------------: | -------------: | --: |
| 公開 `/en/` |         100 |           100 |            100 | 100 |

LCP 0.9 秒、CLS 0、TBT 0 ms。ローカルとの差はネットワーク往復の分だけで、スコアの減点はなかった。`/en/`・`/ja/`・`/en/models/`・`/en/services/kiro/`・`/` がいずれも HTTP 200 で、`html lang` は英語ページが `en`、日本語ページが `ja` であることを確認した。

### 初回のみ検出された事象

最初の 1 回だけ Best Practices が 96 になり、`errors-in-console` に `http://127.0.0.1:4321/favicon.ico` の 404 が記録された。以降の実行（同一ページ 3 回、他 3 ページ）では再現していない。

- ページは `<link rel="icon" type="image/svg+xml" href="/ai-plan-radar/favicon.svg">` を宣言しており、実際のアイコン取得は 200。
- 404 の宛先はオリジン直下の `/favicon.ico` で、サイトの配信パス（`/ai-plan-radar/`）の外にある。GitHub Pages ではユーザーサイト直下のファイルであり、このリポジトリからは制御できない。
- ブラウザがタブ表示用に投機的に要求するもので、サイト側のリンク切れではない。ただし再発しうるため、測定時は 1 回の結果だけで判断しない。

公開サイト（`https://tonbiattack.github.io/ai-plan-radar/`）のデプロイ後の再測定は、この確認時点では未実施。デプロイ後に同じ手順で確認する。

### 再測定の手順

```sh
npm run build
npm run preview            # 別ターミナルで起動したままにする
npx lighthouse http://127.0.0.1:4321/ai-plan-radar/en/ --quiet \
  --chrome-flags="--headless=new --no-sandbox" \
  --output=json --output-path=./lh.json
```

`--only-categories` に複数カテゴリをカンマ区切りで渡すと Lighthouse 13 ではエラーになるため、全カテゴリを測定して JSON から読む。CI には Lighthouse を組み込んでいない（実行時間とスコア変動のため）。リリース前に手動で確認する。

## 未対応・制約

- Lighthouse はトップ・モデル性能・サービス詳細の 4 画面のみ。比較ページや履歴ページ、全操作の組み合わせは未測定。
- スコアはローカル環境の値で、公開サイトの実測値ではない。
- GitHub Pages の規約適合は上記の静的確認に基づく判断で、GitHub による保証ではない。
