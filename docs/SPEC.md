# AI Plan Radar — 仕様書

更新日: 2026-11-14
状態: MVP仕様（初期案）

## 1. 目的
AIサービスの料金、プラン、対応モデル、利用制限を同じ視点で比較・検索できる無料の日本語サイトを作る。大手に限らず OpenCode、Command Code、Logfare、Muse など知名度が比較的低いサービスを積極的に扱う。**更新速度と網羅性を第一の価値**とする。X・ブログ・リリースノート・GitHubなどで新プランやモデル追加を素早く発見し、ソース付きの速報として公開する。未確認情報は未確認と明示し、後から検証・訂正する。

## 2. 対象範囲と方針
- 初期の比較UIは**AIコーディング系サービス**を中心に作るが、ニュース収集対象はAIサービス全般に広げる。大手・マイナーを区別せず掲載する。
- 初期掲載候補: OpenCode、Command Code、Logfare、Muse、Claude Code、Codex、GitHub Copilot、Cursor、Windsurf、Cline など。掲載は各公式情報を確認してから行う。
- **ツール・ホスティングサービス・モデルプロバイダー・個別プラン**を別の概念として管理する。例: OpenCodeというクライアントと、その上で使う各プロバイダーの契約を混同しない。
- 無料・従量課金・サブスクリプションを区別する。月額換算できないものに架空の月額を付けない。
- 「無制限」「使い放題」の文言をそのまま比較軸にせず、公開されているフェアユース、レート制限、トークン/クレジット枠、時間窓、リセット周期を表示する。
- 初期は認証・ユーザー登録・決済・レビュー投稿・サーバーDBなし。
- **運用費用ゼロを原則とする。有料API、従量課金API、クレジットカード登録が必要なAPIは導入しない。** 無料枠のあるサービスも、超過時に自動課金されるものは原則不採用。GitHub Actions/Pagesの利用枠内で運用する。

## 3. MVP画面
### 3.0 速報フィード（トップの主役）
- 新プラン、値上げ・値下げ、利用枠、モデル追加・削除、新規サービスを時系列で掲載
- 情報源リンク、発見日時、サービス名、変更点、確認状態（速報 / 公式確認済 / 訂正 / 取り下げ）を表示
- サービス・話題・情報源・公開日時で絞り込み、最新順を初期表示
- 同一ニュースの重複投稿をまとめ、初報と後続の公式確認を関連付ける
- SNSの投稿本文は転載せず短く要約し、リンク先へ誘導する

### 3.1 トップ / サービス一覧
- キーワード検索（サービス名・プラン名・対応モデル名）
- カテゴリ、価格帯（無料/月額上限）、利用形態、対応モデル、利用枠の公開状況による絞り込み
- サービス名、概要、月額目安（通貨併記）、無料プラン有無、更新日、公式ページリンク
- 並べ替え（名前、価格、最終確認日）。不明な価格は末尾に置く。
- スマホ/PC両対応。キーボード操作可能。

### 3.2 サービス詳細
- プラン別の料金・請求周期・公式プランページ
- 対応モデルと、そのモデルがどのプランで利用できるか
- 制限の種類（リクエスト数、トークン、クレジット、時間/日/週単位、フェアユース、不明）
- 制限対象（プラン全体/モデル別/機能別）、超過時の扱い、繰越/リセット条件（判明時）
- 最終確認日、公式出典、データ確度（公式確認済み/要確認/不明）
- 履歴ページへの導線

### 3.3 比較
- 2〜4プランの横並び比較
- 価格・課金方法・対応モデル・制限・出典・確認日を表示
- 不明と「制限なし」を明確に区別

### 3.4 更新履歴
- サービス/プラン単位の変更日、変更項目、旧値→新値、公式出典
- 実際に観測した変更と、事業者による発効日が異なる場合は区別する
- 比較ができなかった場合は「変更なし」と断定しない

## 4. データ仕様（推奨）
初期はGit管理のJSON。schema定義（JSON SchemaまたはZod）によってビルド時に検証する。

### Service
- id（安定ID）、name、slug、category、description、officialUrl、pricingUrl
- serviceType（client / hosted_agent / model_provider / other）、supportedPlatforms[]
- verifiedAt、sources[]（URL・確認日）、status（active / unverified / discontinued）

### Plan
- id、serviceId、name、billingType（free / subscription / usage / hybrid）
- price（amount、currency、period、taxNote、promotionNote）またはnull
- modelAccess[]（modelId、availability、notes）
- limits[]（scope、metric、amount|null、unit、window、resetPolicy、notes、sourceUrl）
- features[]、verifiedAt、sources[]、notes

### Model
- id、displayName、provider（分かる場合）、aliases[]
- モデル名の表示・フィルター用。サービスごとの表記違いはaliasで吸収。

### NewsItem
- id、serviceIds[]、title、summary、category、sourceType（x / official / github / blog / community / other）
- sourceUrl、publishedAt|null、discoveredAt、status（breaking / verified / corrected / retracted）
- facts[]（変更候補）、relatedIds[]、reviewedAt|null、notes
- 外部の未確認情報は断定しない。原投稿の編集・削除にも耐えるよう記録する。

### WatchSource
- id、serviceId|null、kind（x_account / x_search / rss / github_releases / github_discussions / changelog / webpage / manual）
- urlOrQuery、enabled、priority、pollIntervalMinutes、lastCheckedAt|null、lastSuccessAt|null
- 誰が何を監視しているか、どの収集方式で取得するかをGit管理で設定する。

### Change
- id、observedAt、effectiveAt|null、serviceId、planId|null、field、before、after、sourceUrl、reviewStatus
- 履歴は追記を基本とし、根拠のない自動変更を記録しない。

**重要:** 未公開、未調査、利用不可、制限なし、確認失敗は別の値として扱う。通貨変換はMVPでは行わず、JPYとUSDを混在したまま単純な価格順に並べない。金額は税込/税別、年払い時の月額表示、キャンペーン価格を明記する。

## 5. 技術構成
- Astro + TypeScript、必要な箇所のみクライアントJS。CSSはTailwind CSSを候補とする。
- GitHub Pagesで静的ホスティング。公開URL: https://tonbiattack.github.io/ai-plan-radar/
- GitHub Actionsでlint/test/build/デプロイを行う。
- Astroの `site` と `base` を設定してサブパス下でもCSS/JS/リンクが動作するようにする。
- 一覧・詳細・履歴はビルド時に静的生成。比較やフィルターはブラウザー内で実行。
- データはリポジトリ内に保存し、秘密情報・APIキーをフロント側へ配布しない。
- GitHub Pagesの利用条件を守り、商用化が主目的になった場合は配信先を再検討する。

## 6. ニュース監視・速報更新（最重要）
1. サービスごとに監視対象を設定ファイルで登録する。X公式アカウント、キーワード検索、RSS、公式ブログ、GitHub Releases/Discussions、変更履歴、手動投稿URLをサポートする設計。
2. **複数のAIエージェントから同じ入力形式で投稿可能**にする。Muse、OpenCode、Command Code、Codex、GitHub Actionsなど、実行主体を問わず `news-candidate.json` と出典URLを受け取り、共通スキーマで検証する。特定サービスの専用APIに依存しない。
3. まずはURLを貼るだけで速報候補を登録できる手動CLI/Issueフォームを用意し、その後でRSSやGitHubなどの自動収集を導入する。
4. 収集頻度はソース別に設定可能にする。可能なものは短間隔（例: 15～60分）、GitHub Actionsのスケジュール実行は正確な時刻を保証しないため、遅延可能性を明示する。
5. **Xの有料APIは使わない。** 無料かつ利用条件に適合する公式取得手段が確認できない限り、Xの自動監視は対象外とする。X投稿URLの手動登録や、許可された公開情報・公式ブログ・GitHub等を代替にする。無許可スクレイピングやログイン回避も行わない。
6. 収集→AI要約/分類→重複統合→速報として公開→公式検証→確定情報と料金DBを更新、の二段階フロー。
7. 速報には必ずリンク・発見日時・確認状態を付ける。独立した裏取りがない場合は「未確認」。数値・価格・モデル提供可否の構造化DBへの反映は公式確認後とする。
8. 速報の低リスクな自動公開は許容するが、ソース不在・スキーマ不正・露骨なプロモーション・既知のデマ疑義は保留。修正・取り下げは履歴を残す。
9. 差分・重複判定はURL正規化＋サービス名＋変更内容＋時間窓を利用し、同一情報源の再投稿を抑制する。
10. 手動実行、定期実行、外部エージェント投稿の全経路に同じ検証を適用する。トークン・秘密鍵はGitHub Secretsに保持し、静的データに含めない。外部の有料APIや従量課金AI APIを利用せず、無料枠の上限に達したら処理を停止・延期する。
13. 自動収集は、公開RSS/Atom、GitHub REST API（無料利用可能な範囲とレート制限内）、公式サイトの公開情報を優先する。AI要約は利用中のエージェントによるローカル/手動実行、または追加費用が発生しない方法を採用し、なければルールベース抽出と手動登録に切り替える。
11. 正式な料金DBとニュースフィードは分離する。収集失敗を「変更なし」と扱わず、前回の確認済みデータを維持する。
12. サイト公開時はニュースの出典を示し、誤報の訂正導線を提供する。著作権・API規約・レート制限を順守する。

## 7. 非機能要件
- 日本語優先、価格などは元通貨表示。時刻はISO 8601管理し画面で日本時間表示。
- Lighthouse等でモバイル表示・アクセシビリティ・基本SEOを確認。
- 見出し構造、メタ情報、OGP、sitemap、canonical、必要な構造化データを整備。
- 公式サービスと誤認されない非公式サイト表記を設ける。
- 料金・モデル・制限の「最新性」を保証しない旨と、購入前の公式確認導線を明示。
- 外部API課金は0円を必須条件とし、GitHub Actions等の無料利用枠・実行時間・利用規約を監視する。タイムアウト/失敗通知を設ける。

## 8. 段階的実装
### Phase 1 — まず公開
静的サイト基盤、5〜10サービスのJSON、一覧/詳細、検索・フィルター、**URLからの速報登録・速報フィード**、GitHub Pages公開。

### Phase 2 — 自動ニュース収集を充実
RSS/GitHub/公式更新情報の監視、複数エージェントの候補投稿、重複排除と速報の自動公開。並行してプラン比較・変更履歴を拡充。

### Phase 3 — 高速・広範囲な監視
無料で利用できる公開ソースの監視対象拡張、間隔最適化、ニュースと確認済み料金DBの連携、訂正フロー。有料X APIの導入は予定しない。

### Phase 4 — 拡張
カテゴリ拡大、ユーザーからの掲載申請、お気に入り、変更通知、通貨換算、用途別おすすめ（評価基準明示）。

## 9. MVP受け入れ条件
- [ ] GitHub Pagesでスマホ/PCからアクセスでき、サブパスでもアセットが正常表示される
- [ ] 5サービス以上・複数プランが掲載され、確認状態が明示される
- [ ] X投稿URLや公式URLを手動登録すると出典付き速報として一覧に載る
- [ ] サービス名、モデル名で検索でき、無料/課金方式で絞り込める
- [ ] 詳細ページでプラン価格・制限・確認日・公式リンクがわかる
- [ ] 未確認の内容をゼロや無制限と誤表示しない
- [ ] データ不正時にCIが失敗する
- [ ] セキュリティ情報を静的生成物に含めない

## 10. 対象外（MVP）
アカウント登録、リアルタイムの残クレジット照会、ユーザーごとのAPI接続、アフィリエイト最適化、AIによる主観ランキング、根拠不明の数値を確認済みDBへ自動反映すること。出典付き・未確認ラベル付きの速報自動公開は許容する。
