# AI Plan Radar — 仕様書

更新日: 2026-11-14
状態: MVP仕様（初期案）

## 1. 目的
AIサービスの料金、プラン、対応モデル、利用制限を同じ視点で比較・検索できる無料の日本語サイトを作る。大手に限らず OpenCode、Command Code、Logfare、Muse など知名度が比較的低いサービスを積極的に扱う。**料金だけでなく、実際に何が・どれだけ使えるか**を可視化し、更新履歴と公式出典から情報を追跡できることを価値とする。

## 2. 対象範囲と方針
- MVPは**AIコーディング系サービス**に特化する。後から一般チャット、画像生成、APIプロバイダーなどへ拡張可能にする。
- 初期掲載候補: OpenCode、Command Code、Logfare、Muse、Claude Code、Codex、GitHub Copilot、Cursor、Windsurf、Cline など。掲載は各公式情報を確認してから行う。
- **ツール・ホスティングサービス・モデルプロバイダー・個別プラン**を別の概念として管理する。例: OpenCodeというクライアントと、その上で使う各プロバイダーの契約を混同しない。
- 無料・従量課金・サブスクリプションを区別する。月額換算できないものに架空の月額を付けない。
- 「無制限」「使い放題」の文言をそのまま比較軸にせず、公開されているフェアユース、レート制限、トークン/クレジット枠、時間窓、リセット周期を表示する。
- 初期は認証・ユーザー登録・決済・レビュー投稿・サーバーDBなし。

## 3. MVP画面
### 3.1 トップ / サービス一覧
- キーワード検索（サービス名・プラン名・対応モデル名）
- カテゴリ、価格帯（無料/月額上限）、利用形態、対応モデル、利用枠の公開状況による絞り込み
- サービス名、概要、月額目安（通貨併記）、無料プラン有無、更新日、公式ページリンク
- 並べ替え（名前、価格、最終確認日）。不明な価格は末尾に置く。
- スマホ/PC両対応。キーボード操作可能。

### 3.2 サービス詳細
- プラン別の料金・請求周期・公式プランページ
- 対応モデルと、そのモデルがどのプランで利用できるか
- 制限の種類（リクエスト数、トークン、クレジット、時間/日/週単位、フェアユース、不明）
- 制限対象（プラン全体/モデル別/機能別）、超過時の扱い、繰越/リセット条件（判明時）
- 最終確認日、公式出典、データ確度（公式確認済み/要確認/不明）
- 履歴ページへの導線

### 3.3 比較
- 2〜4プランの横並び比較
- 価格・課金方法・対応モデル・制限・出典・確認日を表示
- 不明と「制限なし」を明確に区別

### 3.4 更新履歴
- サービス/プラン単位の変更日、変更項目、旧値→新値、公式出典
- 実際に観測した変更と、事業者による発効日が異なる場合は区別する
- 比較ができなかった場合は「変更なし」と断定しない

## 4. データ仕様（推奨）
初期はGit管理のJSON。schema定義（JSON SchemaまたはZod）によってビルド時に検証する。

### Service
- id（安定ID）、name、slug、category、description、officialUrl、pricingUrl
- serviceType（client / hosted_agent / model_provider / other）、supportedPlatforms[]
- verifiedAt、sources[]（URL・確認日）、status（active / unverified / discontinued）

### Plan
- id、serviceId、name、billingType（free / subscription / usage / hybrid）
- price（amount、currency、period、taxNote、promotionNote）またはnull
- modelAccess[]（modelId、availability、notes）
- limits[]（scope、metric、amount|null、unit、window、resetPolicy、notes、sourceUrl）
- features[]、verifiedAt、sources[]、notes

### Model
- id、displayName、provider（分かる場合）、aliases[]
- モデル名の表示・フィルター用。サービスごとの表記違いはaliasで吸収。

### Change
- id、observedAt、effectiveAt|null、serviceId、planId|null、field、before、after、sourceUrl、reviewStatus
- 履歴は追記を基本とし、根拠のない自動変更を記録しない。

**重要:** 未公開、未調査、利用不可、制限なし、確認失敗は別の値として扱う。通貨変換はMVPでは行わず、JPYとUSDを混在したまま単純な価格順に並べない。金額は税込/税別、年払い時の月額表示、キャンペーン価格を明記する。

## 5. 技術構成
- Astro + TypeScript、必要な箇所のみクライアントJS。CSSはTailwind CSSを候補とする。
- GitHub Pagesで静的ホスティング。公開URL: https://tonbiattack.github.io/ai-plan-radar/
- GitHub Actionsでlint/test/build/デプロイを行う。
- Astroの `site` と `base` を設定してサブパス下でもCSS/JS/リンクが動作するようにする。
- 一覧・詳細・履歴はビルド時に静的生成。比較やフィルターはブラウザー内で実行。
- データはリポジトリ内に保存し、秘密情報・APIキーをフロント側へ配布しない。
- GitHub Pagesの利用条件を守り、商用化が主目的になった場合は配信先を再検討する。

## 6. 情報収集・更新
1. 公式価格/制限/モデル一覧のURLをサービス単位で管理。
2. GitHub Actionsの手動起動と定期実行（当初1日1回）で情報収集。
3. HTML取得/抽出に失敗したら最後に確認したデータを維持し、失敗ログと検証対象を残す。
4. 差分が見つかれば自動でIssueまたはPRを作成（同一差分の重複防止）。
5. AI抽出は**候補生成**まで。価格・上限・モデル削除等の重要変更は公式根拠を付けたレビュー後に反映する。
6. 更新時にJSON schema、参照整合性、重複ID、必須出典、日付を検証。
7. 公式の利用規約、robots指示、アクセス頻度、レート制限を尊重する。
8. 最終チェック成功日と、データの最終確認日は区別する。

## 7. 非機能要件
- 日本語優先、価格などは元通貨表示。時刻はISO 8601管理し画面で日本時間表示。
- Lighthouse等でモバイル表示・アクセシビリティ・基本SEOを確認。
- 見出し構造、メタ情報、OGP、sitemap、canonical、必要な構造化データを整備。
- 公式サービスと誤認されない非公式サイト表記を設ける。
- 料金・モデル・制限の「最新性」を保証しない旨と、購入前の公式確認導線を明示。
- 自動収集は費用上限/タイムアウト/失敗通知を設ける。

## 8. 段階的実装
### Phase 1 — まず公開
静的サイト基盤、手動確認済み5〜10サービスのJSON、一覧/詳細、検索・フィルター、GitHub Pages公開。

### Phase 2 — 比較価値を高める
プラン比較、対応モデル横断検索、利用制限の明細、更新履歴、情報の鮮度表示。

### Phase 3 — 運用を省力化
GitHub Actionsの定期取得、差分検出、レビュー用PR/Issue、検証・監視の仕組み。

### Phase 4 — 拡張
カテゴリ拡大、ユーザーからの掲載申請、お気に入り、変更通知、通貨換算、用途別おすすめ（評価基準明示）。

## 9. MVP受け入れ条件
- [ ] GitHub Pagesでスマホ/PCからアクセスでき、サブパスでもアセットが正常表示される
- [ ] 公式出典付きの5サービス以上・複数プランが掲載される
- [ ] サービス名、モデル名で検索でき、無料/課金方式で絞り込める
- [ ] 詳細ページでプラン価格・制限・確認日・公式リンクがわかる
- [ ] 未確認の内容をゼロや無制限と誤表示しない
- [ ] データ不正時にCIが失敗する
- [ ] セキュリティ情報を静的生成物に含めない

## 10. 対象外（MVP）
アカウント登録、リアルタイムの残クレジット照会、ユーザーごとのAPI接続、アフィリエイト最適化、AIによる主観ランキング、無審査のデータ自動公開。
